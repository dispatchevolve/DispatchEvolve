## Order-Driver Dispatch Engine

An order-driver dispatch engine assigns ride orders to available drivers.

Input: For each dispatch round, the engine receives a batch containing the orders, available drivers, and possible pairings considered together. Each possible order-driver assignment is an OD pair. An OD pair contains information about the order, driver, and trip, such as pickup distance and estimated arrival time.

Process: The dispatch engine is composed of Policies and Matching. Policies run in a defined order. Some Policies filter out OD pairs that do not meet service or business requirements. Other Policies perform value modeling: they estimate or adjust the expected service and business value of OD pairs and produce values used by Matching. Matching compares the OD pairs left after filtering and selects the assignments for the batch.

Output: The engine returns the selected OD pairs as the order-driver assignments.

Scene: A Scene classifies batches by their batch-level features. These features summarize the overall conditions of a batch, such as the numbers of orders and available drivers, the supply-demand ratio, or the average pickup ETA. Conditions on these features define a Scene, and each batch either belongs to that Scene or does not. For example, “high demand, limited driver supply, and long average pickup ETA” defines one Scene.

## DispatchEvolve

DispatchEvolve uses the Query from this task to select complete batches. The system then executes the current engine on those batches and deterministically measures Policy activity and performance before deciding whether the Scene contains an optimization Opportunity.
